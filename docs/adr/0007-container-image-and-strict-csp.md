# A container image for the Server, with a strict Content-Security-Policy

Emu runs on the Traquenard Server as an image from GHCR, under Kubernetes' Pod Security `restricted`, on arm64. The image (`Dockerfile`) is the locked dependencies in a virtualenv on `python:3.13-slim`, built with uv and copied into a final stage without it. It runs uvicorn on port 8080 as the numeric user 10001, with bytecode compiled at build time, so it needs no capability and writes nothing: it runs with a read-only root filesystem and `/tmp` as a tmpfs. `GET /healthz` answers for the probes without touching the database, so a Postgres restart does not get emu restarted too.

CI (`.github/workflows/ci.yml`) tests every push and pull request, then builds the image on a native arm64 runner and a native amd64 one (no emulation) and smoke-checks each the way the Server runs it (`scripts/smoke-container.sh`: user 10001, read-only, no capabilities, beside Postgres 18, the SQLite importer run inside it). On `main` both are pushed by digest and joined under one tag, `main-<commit unix time>-<short sha>`, which the Server's bump workflow orders by time. Rejected: QEMU emulation for the other platform (slow, and it would smoke-check an emulated build); an arm64-only image (laptops are amd64).

Every response carries a Content-Security-Policy. The Server adds the other security headers and leaves this one to the Project. To make it strict, the inline scripts and the inline stylesheet moved into files under `/static`, server data reaches scripts through `<script type="application/json">` blocks (which never run), and the one `onclick` became a `data-confirm` form. The policy allows only emu's own scripts, styles, images and requests; inline style attributes, which set the CSS variables of the banner words and photo tiles; and `blob:` images, for the barcode photo read in the browser. `tests/test_csp.py` keeps templates from growing inline code again. Rejected: per-request nonces (every inline script would have to remember one) and `'unsafe-inline'` scripts (it gives up most of what the policy protects). The in-browser camera scanner is not governed by this policy but by Permissions-Policy, which the Server's proxy sets to deny the camera until iamPepouze/traquenard-server#221 lets a hostname opt out; scanning from a photo works either way.
